# ADR 0068: the final measurement

This is the record that
[ADR 0068](../adr/0068-a-dynamic-value-is-inspected-in-cove-not-walked-in-rust.md)'s
Phase 5 asks for: "Publish the final static-versus-reflected counts and
performance report". It is kept outside the ADR so that the ADR's body stays
exactly as it was decided. The ADR's header links here, and that header is the
only part of the ADR that has changed.

It was first written by Phase 5a (#517, measured 2026-09-25 at 662010e), when
five issues blocked the phase. **This version is the close**, measured on
2026-09-28 after every one of them was decided: the #514 series (#518–#528),
the empty-path skip that is #512's and #513's last change, and the deletion of
the Rust walkers that is #516. Phase 5a's figures that nothing since has moved
— the per-PR attributions of the series up to #511 — are kept below as they
were published, and are marked as Phase 5a's where they appear.

## Summary

- **Semantics.** AST, VM and native agree everywhere this repository checks
  (§1): `vm_coverage` with an empty known-disagreement set, the e2e suite with
  its native-marked cases, both differential suites, and `cove test` over
  `examples/` on both backends.
- **Every ratchet movement is attributed to a PR** (§3), through #528 and the
  two closing changes.
- **covefmt and cq did not get slower on either tier** (§4, §7). Against the
  binary before ADR 0068 (18d92bd), covefmt is 1.47% fewer VM instructions
  and cq 2.31% / 1.25% fewer; on native, cq `rate-card` is 20.6% faster.
- **The `Intrinsic` count is 3**, none of them ADR 0068's (§3, §6).
- **The Rust walkers are deleted** (#516): `equal.rs`, `key.rs`, their depth
  bound and the per-variant `work` column that only they could fill.
- **Every remaining cost was decided**, and each is listed with the decision
  that closed it under [Accepted residuals](#accepted-residuals).
- **So ADR 0068 is `Accepted`.** The Phase 0–5 checklist at the end is closed
  except Phase 5b, the separate ADR on whether reflection becomes public,
  which is pending by design.

## Method

**Binaries.** Each was built once with
`cargo build --profile checked -p cove-cli --features cove-cli/template`, in
its own `git worktree` under `/tmp`, one build at a time.

| label | commit | role |
| --- | --- | --- |
| before | 18d92bd (#491) | before ADR 0068: Phase 0 pinned, no behaviour change |
| c789eab | c789eab (#528) | after every PR of the series, before the closing changes |
| **final** | c789eab + the empty-path skip + the walker deletion | what this record measures |
| A/A | a byte copy of **final** at a second path | noise control |

The empty-path skip changes only the two static tracked walks (§7), and the
walker deletion only code that runs in this crate's tests, so **final** and
c789eab execute identical instruction streams everywhere except
`benches/equals` and `benches/rendering`, which are 121 instructions per
`tree` operation fewer. That makes c789eab a second, rebuild-sized control for
every other row.

**One pristine tree.** Every binary ran over a single `git worktree` at
c789eab, which was never written to (`git status` is clean afterwards). cq's
input and output lived in a directory outside it, because covefmt walks the
directory in raw order and reads every entry. The only source differences
between that tree and **final** are comments.

**Inputs.**
- covefmt: `cd examples && cove run covefmtBench --files-root ..`, which is
  369 files and 1,782,102 bytes at c789eab (Phase 5a's 363 and 1,750,921 were
  662010e's tree).
- cq `confirmed-bookings`: 100,000 records from
  `cqSample -- 100000 bookings-large.jsonl`.
- cq `rate-card`: the 20,000× `rates.csv` of ADR 0046, 120,000 rows.
- the mechanism benches `benches/equals`, `ordering`, `admission` and
  `rendering`, and #515's flat render probe (one erased two-field struct
  rendered 200,000 times).

**Counters** come from `--stats --boundary`, once per binary and backend:
instructions, allocations, words and crossings are deterministic. The
instructions of one bench row come from `--profile --profile-rows all`,
summed over the row's counting function and the synthesized functions it
calls, and divided by its turns.

**Wall time.** 11 interleaved trials; within each trial every binary ran
every program on both tiers, in an order rotated from trial to trial, with
nothing else running. Every figure is written `median (min–max)`, n = 11,
unless it says otherwise. Bench rows are in ns per operation as the bench
prints them; covefmt's phases in ms as it prints them; "process" is
`/usr/bin/time` real time.

**Noise controls.** The A/A copy; c789eab against **final** wherever the
instruction streams are identical; and, on the bench rows, the rows whose
instruction count did not move.

### What `std.dynamic` still refuses or crosses

- It never crosses to the VM, and no `std.dynamic` function is refused on
  native.
- It stops a run in exactly the places the language requires: a value that
  contains itself under `==` (#496), and a key the language does not admit
  (#498 decides, #507 words it).
- Every observation it makes below Cove is one of §3's structural
  observations, #523's identity set, or `core.refuse`.

### What Rust walks are left

None that walks a value for an operation. #516 deleted `equal.rs` (the dead
`Any.equals` walk) and `key.rs` (the order, which was still a test oracle for
every keyed finish), and `MAX_DEPTH = 128` with them. The keyed-finish check
in `cove-runtime`'s tests now materialises each key with `boundary::to_value`
and orders it by `MapKey`'s derived `Ord` — the oracle's order, not code
under test — and a test shows it failing on a mis-ordered run. What stays is
not an operation: `boundary.rs`'s conversion at the Host boundary and its own
depth bound, the debugger's lossy renderer in `render.rs` and its bound of 24,
and `DynSameObject`, which #523's scan of the first eight path entries uses.

### Static layouts: `tree` (#512, #513)

These are the two rows whose static walk carries a path because the layout
can reach itself through a vector (#496's `tracks<L>`, #502's
`rendersTracked<L>`). The empty-path skip is the one change made to them for
this close: a vector whose path is empty goes straight to becoming the
path's first entry without looking along it, the walk-down loop's first test
moved above the copy that starts it, and the loop leaves from the bottom
instead of taking one more jump to its head. It is exact — a scan of an
empty path cannot find anything — and it applies to both walks generically.
The boxed walks already skip it: `onPath` and `repeats` are expanded inline,
and their loop's first test is the empty-path test.

Instructions per operation, VM (`--profile`, deterministic):

| row | before | c789eab | **final** | final vs before |
| --- | ---: | ---: | ---: | --- |
| equals `tree`, per compare | 6,549 | 9,775 | 9,654 | **+47.4%** |
| rendering `tree`, per render | 33,362 | 37,318 | 37,197 | **+11.5%** |

The skip took 121 instructions off each: one copy at the root, and one jump
at each of the 120 other non-empty vectors of the 364-node tree. What is left
is the look itself, which is linear in the path's depth, 426 entries looked
at per operation: the constant per vector that F4's proposal on #514 already
judged cheaper than a hash enter and leave on shallow trees.
