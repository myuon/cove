# Fuzz regressions

One directory per target. Every file in `<target>/` is an input that once
crashed that harness and no longer does; `crates/cove-fuzz/tests/regressions.rs`
replays each of them under `cargo t`. Files in `<target>/known/` still crash
and are not replayed; each has a line below. See `docs/FUZZING.md`.

| Input | Found | What it was |
|---|---|---|
| `differential/generator-vector-chain-nests-too-deep` | 2026-10-24, `differential`, session without ASan | A generator bug, not a toolchain one: `fresh_vector` built its array at a fixed depth, and an array can be a fresh vector's `toArray()`, so the pair could chain without the depth growing — here 54 `.toVector()).toArray()` links, which the parser refuses (`cove::parse::nesting_too_deep`, correctly). The generated program was refused and `differential` panicked as it should. `fresh_vector` now takes the depth. |
| `run/negation-of-a-return` | 2026-10-24, `run`, CI run 40110666813 ([issue 698](https://github.com/myuon/cove/issues/698)) | `!return x`: the checker types a diverging operand `Never` and accepts it anywhere, and the lowering went on to emit the `not` over the `Unit` slot a diverging expression answers, which the verifier refused (`lower/mod.rs`, "slot 16 holds unit, but this wants bool"). Every unary and binary operator and every fused `if`/`while` comparison did the same; a call argument, an array element, a receiver and an assignment were refused as gaps instead. The lowering now stops a form at the first operand that leaves (`lower/unreached.rs`), and a block at the first statement that does. |
| `differential_source/operands-that-leave` | 2026-10-25, written for issue 698 | The same family on paths that run: an operand evaluated before the one that leaves still runs, a `break` and a `continue` as operands inside a loop, and a recursive `!return`. All six modes agree. |
| `image/span-delta-overflow` | 2026-10-24, `image`, ASan session | `serial::decode` added a span's start delta to the previous span's start, and the end delta to that, unchecked: an `i64` delta near the limits overflowed and panicked (`attempt to add with overflow`, `serial.rs`). Now checked and refused as "a span lands outside a file". |
| `image/field-read-as-another-family` | 2026-10-25, ADR 0120, built by `crates/cove-fuzz/tests/vm_findings.rs` | A `load.field` of a `String`'s payload word 0 as a `String`: the machine took the instruction's layout for what the object held, and read eight bytes of text as an object address. Now held to the object's header (`vm/exec/agree.rs`) and refused as a read of a word as something it is not. |
| `image/lock-on-a-closure` | 2026-10-25, ADR 0120, `vm_findings.rs` | `shared.lock` on a closure object: the compare-and-swap wrote the lock state over the closure's callee word. Now refused unless the object is a `Shared` cell. |
| `image/closure-called-with-another-signature` | 2026-10-25, ADR 0120, `vm_findings.rs` | A closure whose function takes an address, called with an `Int`: a closure call's arguments were copied at the callee's parameter widths and never compared, so the callee loaded and stored through stack address 5. Now held to the callee's parameters and answer (`Machine::closure_callee`). |
| `image/view-forged-over-a-cell` | 2026-10-25, ADR 0120, `vm_findings.rs` | A dynamic view written out of two `Int`s and a reference — the `String` layout over a `Shared` cell — then `dyn.read` as a string: the cell came back as a `String`. Now every observation that follows a view holds it to what `dyn.open` and `dyn.child` answer (`View::held`), and the native tier hands those observations to the runtime. |
| `image/struct-words-disagree-with-fields` | 2026-10-25, ADR 0120, `vm_findings.rs` | `Pair`'s reference word relabelled `Int` in the layout table: the collector stopped tracing the string while a field load still read it as one. Refused by `verify/layouts.rs`. |
| `image/int-slot-read-through-as-a-reference` | 2026-10-25, ADR 0120, `vm_findings.rs` | The address of an `Int` slot loaded through as a `String`. Refused by `verify/places.rs`: the place's need is a reference where the frame holds an `Int`. |
| `ir/place-offset-round-a-loop` | 2026-10-25, `ir-stats` seed 91 | An `addr.of-part` of its own source round a loop: `verify/places.rs`'s per-function fixed point grew the place's need by one offset a round and ran until the frame-wide reach, minutes for one input (`ir-stats` reported it as a hang). Now bounded as the cross-call fixed point is, and refused as a reach that cannot be bounded. |
| `ir/lock-on-an-object-then-a-forged-view` | 2026-10-25, `ir-stats` seed 511 | `vm` and `vm-again` disagreed: a lock on an object that is not a cell, then a view built from `Int` fields of that object and followed by `dyn.on-path` and `dyn.count` into words whose contents depended on the heap. Now the lock is refused, and the view would be. |
| `ir/await-at-another-width` | 2026-10-25, `ir`, ASan session | A task settled with a `Float` and awaited as a `MapEntry`: `await` read the task's answer box at its own three-word width, past the one word the box held (`Memory::read_words`' bound, a `debug_assert`, was all that stopped it). A task handle carries no layout, so the machine now holds an `await` to the layout the task answers, and a `spawn` to its body's return layout. |
| `image/span-names-a-missing-file`, `ir_mutate/span-names-a-missing-file` | 2026-10-25, `image` and `ir_mutate`, ASan sessions | A function's span named file 39 of an image that carries 18. `decode` bounded a span's offsets and not its file, which `encode` refuses; once ADR 0120 ran what decodes, a run that failed attached its call chain and `SourceMap::is_library` indexed past the map (`index out of bounds: the len is 18 but the index is 39`, `cove-diag`). `decode` now refuses a span whose file the image does not hold. |

An `image` input carries the hashes of the standard-library files it names,
so after the standard library changes, `decode` refuses such an input earlier
than the place it once crashed. It still must not panic, which is what the
replay checks, but it no longer reaches that place.

## Known

| Input | Found | What it is |
|---|---|---|
| `image/known/verify-param-layout-out-of-range` | 2026-10-24, `image`, ASan session | A body `decode` accepts whose function names a parameter layout id past the end of the layout table; `cove_ir::verify` then panics in `Function::param_words` (`program.rs`, `index out of bounds: the len is 20 but the index is 75`, from `verify::Check::run`). Not a crash `cove` can reach: images come only from this build, and the `image` target no longer runs `verify` (ADR 0112 §5). Kept as the first thing to fix if images are ever accepted from elsewhere — `decode` checking every id against its table, or `verify` checking them before it indexes. Replay with `cargo run --profile checked -p cove-fuzz -- verify-image <file>`. |
